# Автоматический бенчмарк Android/Termux → VPS

**Без USB-модема и root на Android.** Телефон самостоятельно подключается через мобильную сеть SberMobile либо Wi-Fi Ростелекома. На нём работает Termux, а Python переключает семь VPN-профилей в локальном Mihomo. SSH используется ТОЛЬКО для запуска/остановки origin и монитора CPU/RAM на собственном VPS; компьютер не участвует в передаче тестового трафика.

## 1. Подготовка Termux

Установите [Termux из F-Droid](https://f-droid.org/en/packages/com.termux/) или официального [GitHub](https://github.com/termux/termux-app); не смешивайте установочные источники. На Android ARM64:

```bash
pkg install -y git
git clone https://github.com/detektor133/test_tspu.git
cd test_tspu
bash bench/setup_termux.sh
python bench/phone.py configure
```

Последняя команда попросит **секретную ссылку Mihomo/Clash** из файла `sudo cat /var/lib/test-tspu/subscriptions.txt` на VPS. Вставьте её в Termux по скрытому запросу, без аргументов в shell history. Файл хранится с правами `0600`.

## 2. SSH-ключ с телефона

Нужен заранее разрешённый SSH-доступ **с самого телефона к VPS** (без SSH-агента или порт-форвардинга на ПК). В Termux:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

**Только публичный** ключ добавьте в `/root/.ssh/authorized_keys` на VPS через уже работающую SSH-сессию ПК. Проверьте fingerprint сервера по доверенному источнику и выполните на телефоне:

```bash
ssh root@85.192.41.234 'echo SSH-OK'
ssh -o BatchMode=yes root@85.192.41.234 true
```

Если root SSH запрещён, используйте другого пользователя с разрешениями на мониторинг и запись файлов в `/tmp`, указав `--ssh-user`. Порт меняется флагом `--ssh-port`.

## 3. Испытания двух сетей

На Android **выключите системный VPN** (другой клиент), держите Termux в foreground и разрешите работу без ограничений батареи.

**SberMobile:** Wi-Fi на телефоне выключен, мобильные данные включены.

```bash
cd ~/test_tspu
python bench/phone.py run --vps 85.192.41.234 --network sbermobile \
  --levels 1,8,32,64 --seconds 6 --max-mib 256
```

**Ростелеком:** мобильные данные на телефоне выключены, Wi-Fi Ростелекома включён.

```bash
python bench/phone.py run --vps 85.192.41.234 --network rostelecom \
  --levels 1,8,32,64 --seconds 6 --max-mib 256
```

Выполняются проверки VLESS REALITY, VLESS XHTTP, Hysteria2, TUIC, Shadowsocks, Trojan, AnyTLS. Каждый профиль проверяется уровнями параллельности; фиксируются байты, ошибки, пропускная способность, TTFB, p50/p95/p99 полной задержки и CPU/RAM VPS. Пропущенные/ошибочные тесты **не выдаются за успешные**.

### Два разных типа запусков: проверка соединения и измерение производительности

**Пробный прогон (smoke-test), не бенчмарк устойчивой скорости:**

```bash
python bench/phone.py run --vps ВАШ_IP --network sbermobile \
  --levels 1,2,4 --seconds 6 --max-mib 32
```

Бюджет 32 МиБ делится между 21 сочетанием протокол/параллельность. При быстром
протоколе квота запросов может закончиться **до** заданных шести секунд.
Раньше такой результат ошибочно выводился как полный бенчмарк. Теперь каждая строка
содержит **фактическое/заданное время** и проверяемый статус:
- `ok`: временной интервал выдержан, получено не менее 20 успешных ответов;
- `budget_limited`: лимит полезной нагрузки остановил уровень до завершения времени;
- `insufficient_samples`: время выдержано, но менее 20 успешных ответов;
- `failed`: нет успешных ответов.

Бюджетно-ограниченный уровень остаётся подтверждением реальной передачи данных,
**но не** сопоставимой устойчивой скорости за `--seconds`. В CSV имеются
`measurement_status`, `duration_coverage_pct`, `latency_samples`.
p95 рассчитывается только при не менее 20 успешных ответах, p99 — при 100;
иначе поле пустое и в отчёте показано «—». Старые CSV без этих метаданных
не принимаются за полноценно подтверждённые результаты.

**Для нагрузки** задавайте время и трафик с запасом и сверяйте столбец
«Факт/план, с» перед выводами. Пример с **потенциально большим расходом
мобильного трафика**, запускать только если тариф это позволяет:

```bash
python bench/phone.py run --vps ВАШ_IP --network sbermobile \
  --levels 1,2,4 --seconds 45 --max-mib 512
```

Даже большой бюджет не гарантирует полный интервал при высокой скорости,
а медленные уровни могут не набрать 20 ответов за 45 секунд. В этих случаях
статусы честно останутся неполными; для уточнения увеличьте время или
измените параметры и повторите. Сравнение сетей строится только по полным
замерам с достаточной выборкой и одинаковыми параметрами.

`--max-mib` ограничивает суммарный объём *полезной нагрузки origin*, резервируя запросы по 256 КиБ. **Это не предел всего оплачиваемого трафика**: заголовки, неуспешные запросы, установление соединений, TLS и SSH добавляют байты. При ограниченном тарифе **обязательно уменьшите и параллельность**, например `--levels 1,2,4 --max-mib 32`. Скрипт заранее проверяет, хватит ли бюджета хотя бы на один одновременный запрос на каждый запрошенный поток всех семи профилей; при недостатке лимита останавливается до SSH и нагрузки. Значение `--network` задаёт пользователь, автоматически сетевой интерфейс/оператор не подтверждаются.

## 4. Результат и передача через ADB (не tethering)

Программа сообщает приватную папку вида `~/test-tspu-results/...` с `measurements.csv`, `server-resources.csv`, `environment.json`, `report.md` и `charts/*.svg`. Там же лежат **секретные** `private-mihomo.yaml` и `mihomo.log`, которые нельзя экспортировать в Git или общий каталог.

```bash
termux-setup-storage
python bench/export_results.py ~/test-tspu-results/ИМЯ_ПАПКИ
```

Только разрешённые файлы результатов будут скопированы в Android Downloads. После этого на ПК:

```bash
adb pull /sdcard/Download/test-tspu-results/
```

Здесь ADB используется **только для копирования файлов**. Отчёт можно пересоздать командой `python bench/generate_report.py ПАПКА`.

### Общий сравнительный отчёт двух сетей

После обоих запусков автоматический генератор объединяет показатели при **одинаковом числе параллельных потоков**:

```bash
python bench/compare_runs.py \
  ~/test-tspu-results/ПАПКА_SBERMOBILE \
  ~/test-tspu-results/ПАПКА_ROSTELECOM \
  --output ~/test-tspu-results/compare-networks.md
```

Получится Markdown и SVG-график скорости двух сетей. Если одного профиля/уровня нагрузки нет, генератор ставит «—» вместо выдуманного значения. Для получения файла на ПК можно перенести только `compare-networks.md` и `compare-networks-speed.svg` через обычный файловый обмен Android/ADB, не экспортируя приватные конфиги.

## 5. Ограничения

Origin слушает **только 127.0.0.1:18180 на VPS**, не открывайте этот порт наружу. При потере связи с телефоном страховочный процесс завершит origin и монитор автоматически. Тестирование SSH-контроля из мобильной сети — отдельная зависимость: его блокировка не доказывает блокировку VPN.

Время телефона и VPS должно быть синхронизировано для правильной привязки CPU/RAM. Измерение `127.0.0.1` выполняется **через выбранный VPN**, а не с самого телефона. TTFB не равен чистому RTT. Ошибки и деградация сами по себе не доказывают вмешательство ТСПУ; нужны повторные испытания из нескольких сетей.

В автоотчёт входят исходные цифры, графики, гипотеза выбора основного REALITY и технические ограничения; фактическое время разработки, стоимость VPS и рабочую ссылку клиента для проверяющего необходимо дополнить отдельно. Весь тест только на собственном сервере.
