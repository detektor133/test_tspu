# Полевые испытания производительности туннеля

Этот набор предназначен для **реального испытания с двух точек**: VPS за рубежом и клиент в российской сети. Команды не заменяют испытание доступности через ТСПУ. GitHub Actions использует эти же измерители только для локальной проверки их работоспособности.

## 1. Подготовить VPS

Разверните `deploy.sh` по инструкции из корневого README и убедитесь, что подписка импортирована в клиент Mihomo. Для измерения нужен **собственный VPS**, который будет оставаться доступным семь дней после сдачи; в этом репозитории он не предоставлен.

На VPS запустите контрольный HTTP-сервер с файлом 1 МиБ (слушает **только `127.0.0.1`**, не открывайте порт в UFW/cloud firewall):

```bash
python3 bench/origin.py --port 18180 --size 1048576
```

Он выведет SHA256 неизменной нагрузки. Сохраните его для `--sha256` на клиенте. Если клиентский Mihomo не может связаться с адресом `127.0.0.1:18180` **через туннель**, исследуйте причину — не открывайте сервис наружу ради обхода ошибки. На VPS запустите в отдельном терминале монитор процессов **одновременно** с нагрузкой:

```bash
sudo python3 bench/server_monitor.py \
  --duration 100 --interval 1 --output server-mihomo.csv
```

CSV содержит CPU и RSS отдельно для m-ui и Mihomo. **100% CPU — одна полностью загруженная логическая нить**; на нескольких ядрах значение может превышать 100%. RSS — используемая физическая память процесса, не размер всего VPS. Монитор пишет данные без URL, UUID, паролей и адресов клиентов.

## 2. Подготовить клиентскую машину в РФ

Возьмите с сервера ссылку подписки (`sudo cat /var/lib/test-tspu/subscriptions.txt`), импортируйте в Mihomo или совместимый клиент и включите **глобальное проксирование** выбранного профиля. Не включайте обход частных адресов для цели `127.0.0.1:18180`, иначе измерите свой ноутбук вместо VPS. Локальный HTTP-порт клиента в примере — `7890`; уточните его в своём клиенте.

Запишите **оператора, город, тип доступа (LTE/5G/проводной), время, IP/ASN VPS, версию клиента и SNI** в личные заметки. Используйте одинаковые параметры для каждого протокола и сравнивайте в разные моменты суток.

На клиенте запустите:

```bash
python3 bench/http_benchmark.py \
  --url http://127.0.0.1:18180/payload \
  --proxy http://127.0.0.1:7890 \
  --sha256 ВСТАВЬТЕ_SHA256_ИЗ_ВЫВОДА_СЕРВЕРА \
  --min-bytes 1048576 \
  --levels 1,8,32,64 \
  --seconds 20 \
  --timeout 10 \
  --label 'REALITY — МегаФон LTE' \
  --output results-reality-megafon.csv
```

Этот запуск длится примерно **80 секунд плюс время последних HTTP-запросов**, а не 170-секундный лимит CI. Для испытаний ТСПУ можно увеличить продолжительность и повторить 3–5 раз в разное время. В другом прогоне переключите профиль на Hysteria2 / VLESS XHTTP и поменяйте `--label`/имя файла.

В CSV сохраняются: число потоков; успешные/ошибочные запросы; подтверждённые байты полезной нагрузки; throughput в МиБ/с; p50/p95 времени до первого байта (TTFB) и p50/p95/p99 полной загрузки ответа. **RTT измеряется отдельно** (`ping`/`mtr`) — TTFB включает TCP/TLS/прокси/HTTP и не равен чистому RTT. Benchmark использует **новое HTTP-соединение для каждого запроса**; на высоком числе потоков значительную долю может составить стоимость рукопожатий.

### Что означают цифры и чего они не означают

- Измерение к локальному origin на VPS охватывает **сеть клиент ↔ VPS, шифрование и обработку прокси**. Выход с VPS к зарубежным сайтам в нём практически не участвует.
- Не выдавайте throughput внутри одного GitHub runner за скорость из России и не смешивайте скорость прокси с производительностью исходного сайта.
- Для контроля проведите отдельную серию через **разрешённый публичный HTTP(S) origin**, используя `--direct` с аналогичным URL. Не сравнивайте `--direct` для `127.0.0.1` с туннельным измерением — это **разные машины**.
- Если успешность падает только у одного провайдера или при достижении определённого объёма трафика, это **наблюдение**, а не доказательство причины на уровне DPI. Сопоставьте время, объём, ошибки, смену IP, DNS, потерю пакетов и поведение на альтернативном протоколе.
- Не проводите нагрузочные тесты чужих серверов без разрешения; контрольный endpoint находится на вашем VPS и ограничен `127.0.0.1`.

## 3. Что сдавать

Передайте с отчётом CSV `results-*.csv` и `server-mihomo.csv` (после проверки, что в именах файлов нет личных данных). Заполните таблицы в [`REPORT.md`](../REPORT.md): средняя/пиковая CPU, пиковый RSS, latency p95, throughput, число ошибок, найденный предел одновременных потоков, условия сети и даты. В отчёте отделите фактические измерения от предположений.

**Важно:** приложение работодателя требует доступный сервер ещё **7 дней после сдачи** и допускает компенсацию чека до 500 ₽/$5. Реальную аренду и проверку из РФ этим репозиторием заменить нельзя.
